# Sloth Domain Context & Ubiquitous Language

This document defines the domain model, hardware inventory, network topology, and ubiquitous language of the `sloth` home cluster.

---

## 1. Hardware & Operating System Domain

| Term | Definition |
|------|------------|
| **Radxa Rock5B Nodes** | 3-node single-board computer (SBC) control-plane/storage cluster powered by Rockchip RK3588 (`linux/arm64`, 8-core Cortex-A76/A55) running immutable **Kairos Linux (`kairos-rock5b`)** built from pure **Debian 13 Trixie (`trixie-backports` `7.2+` mainline kernel)** and **Mainline U-Boot (`v2026.10`)** on SPI NOR + NVMe SSDs (see [`docs/hardware/rock5b-cluster.md`](./docs/hardware/rock5b-cluster.md)):<ul><li>`rock5b-but` (`192.168.1.21`) — `control-plane,etcd,monitoring,speaker,storage`</li><li>`rock5b-first` (`192.168.1.22`) — `control-plane,etcd,monitoring,speaker,storage`</li><li>`rock5b-coffee` (`192.168.1.23`) — `control-plane,etcd,monitoring,speaker,storage`</li></ul> |
| **`pi0-lcn` (Raspberry Pi Zero 2 W)** | Dedicated 512 MB (`~462 MiB` usable with `gpu_mem=16`, `max_framebuffers=0`, in-RAM `zram` swap, and `/tmp=64M` / `/var/log=32M` `tmpfs` caps) edge K3s agent node (`192.168.1.24`) powered by Broadcom BCM2710A1 (`linux/arm64` Cortex-A53) running DietPi 64-bit Trixie (`6.18.y+rpt-rpi-v8`) over Wi-Fi. Labeled `node-role.kubernetes.io/lcn-serial: "true"` and `node-role.kubernetes.io/monitoring: "true"`, and tainted `dedicated=lcn-serial:NoExecute` so only `reverselcn` and `prometheus-node-exporter` schedule onto it. Exposes the physical LCN-PKU USB serial coupler as `/dev/lcn-pku` (`0660` `root:dialout`) via [`node-bootstrap/pi0-lcn/playbook.yml`](./node-bootstrap/pi0-lcn/playbook.yml). |
| **Declarative Node Roles (`nodes/`)** | Server-Side Applied `v1/Node` manifests ([`argocd-base/nodes.yaml`](./argocd-base/nodes.yaml), dedicated `AppProject: nodes`, `sync-wave: "-1"`, `Prune=false,Delete=false`) that declaratively assign single-purpose scheduling roles without manual `kubectl label` steps:<ul><li>`node-role.kubernetes.io/storage: "true"` — targets Longhorn manager and driver pods onto the 3 Rock5B nodes.</li><li>`node-role.kubernetes.io/speaker: "true"` — targets MetalLB L2 ARP/NDP speaker pods onto the wired Rock5B nodes.</li><li>`node-role.kubernetes.io/monitoring: "true"` — targets `prometheus-node-exporter` onto opted-in nodes (`rock5b-*` and `pi0-lcn`).</li><li>`node-role.kubernetes.io/lcn-serial: "true"` — targets `reverselcn` (`lcn2mqtt`) onto `pi0-lcn`.</li></ul> |
| **NVMe & SPI Boot Partition Layout** | On Kairos OS nodes, Mainline U-Boot EFI (`v2026.10`) lives in onboard 16 MB SPI NOR flash (`/dev/mtd0`) so no permanent MicroSD card is needed, and the 1 TB M.2 NVMe SSD (`/dev/nvme0n1`) uses the full-disk Kairos GPT layout:<ul><li>`COS_GRUB` (`nvme0n1p1`): FAT32 ESP holding `/EFI/BOOT/BOOTAA64.EFI` and `/dtb/rockchip/rk3588-rock-5b.dtb`.</li><li>`COS_OEM` (`nvme0n1p2`) & `COS_RECOVERY` (`nvme0n1p3`) & `COS_STATE` (`nvme0n1p4`, A/B `active.img` / `passive.img`).</li><li>`COS_PERSISTENT` (`nvme0n1p5`): Remainder of NVMe bind-mounted to `/etc/rancher`, `/var/lib/rancher`, `/var/lib/kubelet`, `/var/lib/longhorn`, `/var/lib/iscsi`, and `/etc/iscsi` (50 GiB reserved in Longhorn via `storageReserved: 53687091200`).</li></ul>*(Historically prior to `2026-11-14`, Armbian nodes used 4 GiB SD `/boot` + `94 GiB` Btrfs `/` + `~837 GiB` `ext4` Longhorn `/dev/nvme0n1p2`; see [`docs/hardware/rock5b-cluster.md`](./docs/hardware/rock5b-cluster.md)).* |
| **K3s HA Control Plane & API VIP (`kube-vip`)** | Lightweight Kubernetes distribution (`v1.37.2+k3s1`) initialized with embedded HA `etcd` (`--cluster-init` on `192.168.1.21`), explicit IPv4 `node-ip` (`192.168.1.21–23`) and `tls-san` (`192.168.1.20`, `api.internal.k8s.example.com`, `api.rock.k8s.example.com` rendered via `CLUSTER_DOMAIN`) pinned in `/etc/rancher/k3s/config.yaml`, and bundled `traefik` and `servicelb` disabled (`--disable traefik --disable servicelb`). [`kube-vip`](./cluster-essentials/kube-vip.yaml) (`0.11.2` / `v1.2.4`) runs in control-plane ARP mode (`cp_enable: true`, `svc_enable: false`, `plndr-cp-lock` Lease in `kube-system`) to float **`192.168.1.20`** (`api.internal.k8s.example.com`, `api.rock.k8s.example.com` declared in `sloth-private/cluster-essentials/external-dns-config/k8s-api-dns.yaml`) on `enP4p65s0` across the 3 Rock5B control-plane nodes. |
| **System Upgrade Controller** | Rancher [`system-upgrade-controller`](./cluster-essentials/system-upgrade.yaml) deployed in `system-upgrade` namespace. Executes automated rolling K3s upgrades (`agent-plan` pinned to `v1.37.2+k3s1` in [`k3s.yaml`](./cluster-essentials/system-upgrade-config/k3s.yaml)) for non-Kairos nodes (`kairos.io/managed: DoesNotExist`) with `concurrency: 1` and `cordon: true`. |
| **Kairos Operator (`kairos-operator`)** | Upstream [`kairos-operator`](./cluster-essentials/kairos-operator.yaml) (`v0.3.0`) deployed in `kairos-operator` namespace alongside [`kairos-os.yaml`](./cluster-essentials/kairos-operator-config/kairos-os.yaml) (`NodeOpUpgrade`). Reconciles Day-2 atomic A/B OS + Kernel + K3s OCI image upgrades (`ghcr.io/mychaos87/kairos-rock5b`) across nodes labeled `kairos.io/managed: "true"`. |

## 2. GitOps & Argo CD Domain

| Term | Definition |
|------|------------|
| **App-of-Apps Pattern** | Hierarchical Argo CD reconciliation topology rooted in [`argocd-base/`](./argocd-base/):<ol><li>`argocd` self-manages the Argo CD installation in `argocd`.</li><li>`nodes` reconciles declarative `v1/Node` labels and taints in [`nodes/`](./nodes/) (`AppProject: nodes`).</li><li>`argocd-cluster-essentials` reconciles [`cluster-essentials/`](./cluster-essentials/) (`AppProject: cluster-essentials`).</li><li>`argocd-deployments` reconciles [`deployments/`](./deployments/), which fans out to [`deployments/oidc/oidc.yaml`](./deployments/oidc/oidc.yaml) (`AppProject: oidc`) and [`deployments/smarthome/smarthome.yaml`](./deployments/smarthome/smarthome.yaml) (`AppProject: smarthome`).</li><li>`private` (defined in companion repo `sloth-private/argocd-base/private.yaml`) reconciles private-only workloads under `AppProject: private`.</li></ol> |
| **Multi-Source Application & Private Overlay (`$private`)** | An Argo CD `Application` specifying `spec.sources` (plural) to combine an upstream Helm chart (`spec.sources[0]`) with `$private/values/<app>.yaml` overlays, in-repo Kubernetes manifests, or private `SealedSecret` paths in `sloth-private` (`ref: private`). Used by `argocd-base`, `argocd`, `external-dns`, `longhorn`, `metallb-config`, `prometheus`, `authelia`, `grafana`, `victoria-metrics`, `mosquitto`, and `automqttion`. See [`docs/PRIVATE_OVERLAY.md`](./docs/PRIVATE_OVERLAY.md). |
| **Single-Source Application** | An Argo CD `Application` specifying `spec.source` (singular) pointing either to an upstream Helm chart (`sealed-secrets`, `kube-vip`, `traefik`, `cert-manager`, `kairos-operator`, `version-checker`, `telegraf`, `reverselcn`), a manifest directory in Git (`nodes`, `cert-manager-config`, `external-dns-config`, `longhorn-config`, `kairos-operator-config`), or a Kustomize overlay in Git (`system-upgrade`). |
| **SealedSecret (`*.sealed.json`)** | Asymmetric-encrypted Kubernetes secret resource (`bitnami.com/v1alpha1`) generated by [`create-and-seal-*.sh`](./docs/TOOLCHAIN.md) into `SLOTH_PRIVATE_DIR` (`../sloth-private`) and decrypted exclusively inside the cluster by the `sealed-secrets` controller in `sealed-secrets`. |

## 3. Networking, DNS & PKI Domain

| Term | Definition |
|------|------------|
| **MetalLB L2 Address Pools** | Bare-metal ARP/NDP Layer-2 load balancer ([`cluster-essentials/metallb-config/`](./cluster-essentials/metallb-config/)) managing two IP ranges on the `192.168.1.0/24` LAN:<ul><li>`metallb-reserved-pool` (`192.168.1.30–192.168.1.49`, `autoAssign: false`): Reserved for static service bindings via `metallb.universe.tf/loadBalancerIPs` (e.g., `mosquitto` at `192.168.1.30`).</li><li>`metallb-auto-pool` (`192.168.1.50–192.168.1.99`, `autoAssign: true`): Dynamically assigned to `LoadBalancer` services such as `traefik`.</li></ul> |
| **Split-Horizon Internal Domains (`$private/values/*.yaml`)** | Internal services are exposed on LAN IP addresses under private domain overlays (shown here with `example.com`):<ul><li>`*.rock.k8s.example.com` (e.g., `argocd.rock.k8s.example.com`, `longhorn.rock.k8s.example.com`, `prometheus.rock.k8s.example.com`, `grafana.rock.k8s.example.com`, `victoria.rock.k8s.example.com`, `mqtt.rock.k8s.example.com`)</li><li>`*.internal.k8s.example.com` (e.g., `argocd.internal.k8s.example.com`, `sso.internal.k8s.example.com`, `grafana.internal.k8s.example.com`, `prometheus.internal.k8s.example.com`, `victoria.internal.k8s.example.com`, `mqtt.internal.k8s.example.com`)</li></ul> |
| **ExternalDNS (`google` provider)** | Watches Kubernetes `Service` and `Ingress` resources and synchronizes `A` and `TXT` ownership records (`txtOwnerId: default`) to Google Cloud DNS (GCP project configured via `$private/values/external-dns.yaml`, e.g., `example-dns`) using `policy: sync`. |
| **Cert-Manager (`letsencrypt` ClusterIssuer)** | Provisions public Let's Encrypt TLS certificates for internal domains using ACME **DNS-01** challenges against Google Cloud DNS (configured in `sloth-private/cluster-essentials/cert-manager-config/`), avoiding the need to expose ports 80/443 to the public internet. |
| **Authelia OIDC & ForwardAuth SSO** | Lightweight Identity Provider (`sso.internal.k8s.example.com` / `sso.rock.k8s.example.com`, cookie domain `k8s.example.com`) providing Passkey/WebAuthn + Argon2id OIDC SSO with PKCE for Argo CD and Grafana (`admins`/`editors`/`viewers` group RBAC) plus Traefik `ForwardAuth` (`oidc-chain-authelia-auth@kubernetescrd`) for Longhorn, Prometheus, and VictoriaMetrics UIs. |

## 4. Smarthome & Telemetry Domain

| Term | Definition |
|------|------------|
| **Mosquitto (`192.168.1.30:1883`)** | Eclipse Mosquitto MQTT broker deployed in `mosquitto` namespace (`deployments/smarthome/mosquitto/`), bound to static IP `192.168.1.30` with ExternalDNS hostnames injected from `$private/values/mosquitto.yaml` (e.g., `mqtt.internal.k8s.example.com`, `mosquitto.rock.k8s.example.com`). |
| **Shelly Gen1 (`shellies/#`)** | 1st-generation Shelly relays and sensors publishing raw payloads to `shellies/<device_type>-<device_id>/...` topics, parsed by Telegraf into the `shellies` measurement (`power`, `energy`, `temperature`, `overtemperature`). |
| **Shelly Plus (`shellies_plug/#`)** | Gen2/Plus Shelly smart plugs publishing JSON status objects to `shellies_plug/<device_type>-<device_id>/status/switch:0`, parsed by Telegraf into `shellies_plug` (`apower`, `voltage`, `current`, `temperature_tC`). |
| **Shelly BLU (`shellies_blu/BLE/ht/#`)** | Bluetooth Low Energy temperature/humidity/illuminance sensors forwarded via Shelly gateways to `shellies_blu/BLE/ht/<device>`, parsed into `shellies_blu` (`temperature`, `humidity`, `illuminance`, `battery`). |
| **WARP2 Wallbox (`warp2/22hg/#`)** | Tinkerforge WARP2 EV charger publishing JSON meter values and charging states to `warp2/<id>/<type>` and `warp2/<id>/<type>/<subtype>`, parsed by Telegraf into `wallbox` (`power`, `energy_abs`, `energy_rel`, per-phase currents/voltages). |
| **Pluggit Ventilation (`192.168.1.19:502`)** | Pluggit residential heat-recovery ventilation unit polled over **Modbus TCP** (`slave_id = 1`) by Telegraf every 10 seconds into `pluggit_modbus` (`prmRamIdxT1` outdoor, `T2` supply, `T3` extract, `T4` exhaust temperatures, `prmHALTaho1`/`2` fan speeds, bypass state, VOC, filter remaining time). |
| **Telegraf (`telegraf`)** | Active-active 2-replica metric collector in `telegraf` namespace (`replicaCount: 2`, hard `podAntiAffinity` across `kubernetes.io/hostname`, `omit_hostname: true`, `metric_buffer_limit: 100000`) combining 8 MQTT consumer inputs (`tcp://mosquitto.mosquitto.svc.cluster.local:1883`) and 1 Modbus TCP input (`workarounds.close_connection_after_gather: true`), writing gzipped InfluxDB Line Protocol (`outputs.influxdb`) to `http://victoria-metrics.victoria-metrics.svc.cluster.local:8428/influx`. |
| **VictoriaMetrics (`victoria-metrics`)** | Single-node columnar time-series database (`victoria-metrics-single` `0.50.0` / `v1.155.0`) in `victoria-metrics` namespace (`mode: deployment`, `strategy: Recreate`, `retentionPeriod: 100y`, `dedup.minScrapeInterval: 1s`) backed by a 16 GiB Longhorn PVC, with ingestion relabeling (`labeldrop` on `host`, field normalization on `temperature_temperature`/`humidity_humidity`), bidirectional soft `podAntiAffinity` against `mosquitto`, and **MetricsQL** query engine for Grafana. |
| **Grafana Sidecar Dashboards** | Declarative Grafana dashboards stored as Kubernetes `ConfigMap` manifests labeled `grafana_dashboard: "1"` in [`deployments/smarthome/grafana-dashboards/`](./deployments/smarthome/grafana-dashboards/), hot-reloaded by the `grafana-sc-dashboard` sidecar container. |
| **`reverseLCN` (`lcn2mqtt`)** | Bidirectional Local Control Network (LCN-PKU USB serial coupler at `/dev/lcn-pku`, 9600 8N1) $\leftrightarrow$ Mosquitto (`lcn/segment/#` & `lcn/in`) bridge deployed as a `DaemonSet` in `reverselcn` namespace ([`deployments/smarthome/reverselcn.yaml`](./deployments/smarthome/reverselcn.yaml)) targeting `node-role.kubernetes.io/lcn-serial: "true"` (`pi0-lcn`). Runs unprivileged (`UID 10001`, group `dialout` `20`, `capabilities.drop: ["ALL"]`). |
